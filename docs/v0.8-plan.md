### M46 — Multi-file `--set` per call carve-out fold (D2 closure from v0.6-M38)

**Status:** PRE-FLIGHT contract diff shipped at `7daffaf`.
IMPL lifts the c8-ignored stub bodies in a separate session per
workflow.md "Pre-flight contract diff discipline" (the 6-step
sequence: probe → pre-flight diff → Codex pre-flight → IMPL → Codex
IMPL → close-docs).

**Wire surface:** N `add_file_to_column` legs per item, sequenced
within each item, dispatched across the (single-item / bulk
matched-set / create-time freshly-created) target via the
respective dispatch helper. No new wire op; reuses v0.4-M31's
multipart wire + v0.6-M38's `executeFileColumnSet` runtime body
verbatim, called N times per item.

**Empirical probe NOT required at pre-flight** (wire surface is
known + cassette-pinned at v0.4-M31; novelty is the per-item
multi-leg fan-out + atomicity envelope shape, which is
implementation work, not wire-shape work).

**Open decisions at pre-flight — CLOSED at M46 pre-flight contract
diff (this commit):**

- **D1 — Per-item multi-leg ordering.** ✅ **Closed at v0.8-M46
  pre-flight contract diff: sequential within an item; cross-item
  parallelism reuses M42's `dispatchParallel` (parallel ACROSS
  items, sequential WITHIN each item's file legs).** Sequential
  within-item preserves the partial-failure surface accuracy —
  `details.applied_file_columns` echoes the file columns that
  succeeded before the failure in the order they fired. Parallel
  within-item would surface a non-deterministic `applied_file_
  columns` slot; the trade-off (slight latency win) is not worth
  the partial-failure-debugging cost. Cross-item parallelism stays
  unchanged from M42 D1 (`--concurrency` controls cross-item
  parallel workers; each worker's per-item multi-leg fan-out is
  sequential). No new probe required.

- **D2 — Multi-file partial-failure envelope shape.** ✅ **Closed
  at v0.8-M46 pre-flight contract diff: orphan-warn-style for
  single-item update; per-item shape extends M25's partial-success
  for bulk; extended `create_then_file_upload_partial_failure`
  discriminator for create-time.** Concrete shapes:
  - **Single-item `item update` multi-file partial failure:**
    `internal_error` with `details.reason:
    'multi_file_update_partial_failure'` carrying
    `details.item_id` + `details.applied_file_columns: [<col_ids>]`
    (file columns that landed before the failure, in dispatch
    order) + `details.failed_file_column: <col_id>` +
    `details.cause` (underlying error from M31's pinned surface —
    `column_archived` / `validation_failed` / `not_found` /
    `file_too_large`) + `details.hint` directing the agent to
    retry the unfailed file columns OR reissue all N legs.
  - **Bulk multi-file per-item failure under `--continue-on-error`:**
    Per-item `data.results[i].error: {code, message}` (mirrors
    M42's partial-success shape) extended with
    `data.results[i].applied_file_columns: [<col_ids>]` +
    `data.results[i].failed_file_column: <col_id>` when the
    per-item failure happened mid-multi-leg. The aggregate
    `data.summary` extends M42's `bulkFileSetDataSchema` with
    new `file_count` slot reflecting the N files per item that
    the call attempted.
  - **Bulk multi-file fail-fast (default):** Top-level error with
    `details.applied_to: [<item_ids>]` (items with ALL file legs
    succeeded) + `details.applied_file_columns_per_item: {[item_id]:
    [<col_ids>]}` (per-item partial-leg-success map for the item
    where the failure fired) + `details.failed_at_item: <item_id>` +
    `details.failed_file_column: <col_id>`. Mirrors v0.1 fail-fast
    bulk-update decoration extended with the multi-leg slot.
  - **Create-time multi-file:** Existing M43 discriminator
    `create_then_file_upload_partial_failure` EXTENDED — slot
    `details.applied_file_columns: [<col_ids>]` becomes always-
    present (length 0..N-1 reflecting file columns that landed
    after `create_item` leg-1 succeeded but before the failing
    file leg). Length 0 corresponds to M43's single-file failure
    case (leg-2 fails immediately); length k>0 corresponds to M46
    multi-file partial failure after k file legs succeeded. The
    literal `create_then_file_upload_partial_failure` stays stable
    across single + multi cases (extending an existing payload is
    schema-additive per §6.1).

- **D3 — Pre-check ordering.** ✅ **Closed at v0.8-M46 pre-flight
  contract diff: single upfront pass over ALL file paths before
  any wire call.** Mirrors M42 D3 + M43 D-equivalent. For single-
  item N-file: N paths × 1 pre-check upfront. For bulk N-file: N
  paths × 1 pre-check upfront (shared across the matched-item
  set). For create-time N-file: N paths × 1 pre-check upfront.
  Any pre-check failure aborts the whole call regardless of
  `--continue-on-error` per cli-design §5.8 "pre-checks MUST fire
  BEFORE any wire round-trip". The `--continue-on-error` flag
  partitions ONLY wire-dispatch failures (per-leg
  `add_file_to_column` rejections from Monday), never local file
  pre-check failures.

- **D4 — ERROR_CODES delta.** ✅ **Closed at v0.8-M46 pre-flight
  contract diff: ZERO net change. Registry stays at 29.** All
  M46-specific rejections route through existing codes:
  - Local file pre-check failures → `usage_error` with
    `details.reason: 'file_not_readable'` / `'file_empty'`
    (existing M31 discriminators reused).
  - Mixed mutex violations → `usage_error` with `details.reason:
    'mixed_file_and_value_sets'` (unchanged — universal rule on
    `'item_update_single'` / `'item_update_bulk'`; SUPPRESSED on
    `'item_create'` per M43 D6 asymmetry; multi-file allowance
    does NOT lift mixed-rule).
  - Single-item multi-file partial failure → `internal_error` with
    `details.reason: 'multi_file_update_partial_failure'` (NEW
    discriminator extending R-v0.6-NEW-2 graduated pattern; 6th
    instance — graduated helper absorbs cleanly).
  - Bulk multi-file per-item failure under fail-fast → existing
    v0.1-shaped top-level error with `details.applied_to` etc.
    extended (slot-additive, schema-additive — non-breaking).
  - Create-time multi-file partial failure → existing
    `create_then_file_upload_partial_failure` (extended with
    `details.applied_file_columns` always-present slot — schema-
    additive).

  The `'multi_file_set_unsupported'` discriminator literal at
  `src/api/file-column-set.ts:583` no longer surfaces from the
  runtime path for the 3 reachable callShapes (`'item_update_single'`
  / `'item_update_bulk'` / `'item_create'`) post-M46 carve-out
  fold; the literal stays RESERVED across the codebase (do not
  reuse for a different rejection reason; mirrors M42/M43 reserved-
  literal discipline). The throw at the `'item_set'` callShape is
  argv-unreachable (single-positional `<col>=<value>` shape; 2+
  file `--set` cannot be expressed in argv); kept as defensive
  type-system ceiling, not as a live runtime rejection.

- **D5 — Mixed file + value `--set` interaction.** ✅ **Closed at
  v0.8-M46 pre-flight contract diff: NO CHANGE to mixed-rule
  semantics.** Keeps `'mixed_file_and_value_sets'` rejecting on
  `'item_update_single'` / `'item_update_bulk'` for 1+ file `--set`
  + any value `--set` / `--set-raw` / `--name`. Stays SUPPRESSED
  on `'item_create'` (M43 D6 asymmetry preserved — `create_item`
  natively bundles non-file `column_values` into leg-1 atomically).
  M46 scope is "lift the multi-file leg only"; mixed-rule lift is
  a separate future milestone if demand surfaces (would require

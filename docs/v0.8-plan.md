1000-row hard cap on user pagination). v0.8's load-bearing work is
the user-entity contract migration, NOT new feature surface area —
the new wire surface (`users.activity_logs` + `user_configs`) is
secondary scope.

**Wire surface:** Existing `Query.users` + `User` shape — same wire

**Empirical probe required at pre-flight:**

- Type-change probe — what TypeScript types does SDK 16.x ship
  for the three changed `User` fields (`created_at`, `birthday`,
  `utc_hours_diff`)? Was the change ISO-string ↔ Date object,
  string ↔ number, or something else? Drives the projection
  re-shape design.
- 1000-row cap probe — does Monday's `Query.users(limit: ...)`
  reject `limit > 1000` with `validation_failed`, or silently
  cap? Drives the `user list --all` warning shape.
- Deprecated-args behavior probe — do the three deprecated
  `Query.users` args (`kind`, `newest_first`, `non_active`)
  still function at API `2026-07`, or do they return
  `validation_failed`? Drives migration timing (graceful
  degradation with deprecation warning vs immediate removal).

**Open decisions at pre-flight:**

- **D1 — Type-change projection design.** Three sub-decisions
  (one per changed field) — each driven by the type-change probe
  results. Likely D1a / D1b / D1c at pre-flight.
- **D2 — Deprecated `Query.users` args handling.** Options:
  (a) Remove the CLI flags that consumed the deprecated args
      (clean break — agents update at v0.8 cutover).
  (b) Keep CLI flags but surface a deprecation warning + map to
      the non-deprecated equivalents at the wire boundary
      (graceful — agents migrate over the v0.8.x window).
  (c) Mark CLI flags as deprecated in `--help` but keep
      forwarding the args verbatim (Monday's deprecation warning
      surfaces); transition once Monday drops the args.
- **D3 — 1000-row cap warning shape.** `monday user list --all`
  needs to surface a warning when the requested page size +
  cumulative pagination would exceed 1000 rows. Warning shape:
  envelope-level `warnings: [{code: 'user_pagination_capped',
  ...}]` with `details.cap: 1000` + `details.hint` pointing at
  narrowing filters. Mirrors v0.3-M23's `cross_board_truncated`
  warning shape.
- **D4 — New `User` fields projection subset.** Which of the 10
  new 2026-07 `User` fields land in `monday user get` /
  `monday user list` projections? Likely: `account_id`,
  `status`, `photo_url`, `is_deleted`, `is_email_confirmed`
  (agent-useful). Skip: `serial_number`, `bb_visitor_id`,
  `became_active_at`, `invitation_method` (niche / internal) +
  `user_config` (deferred to v0.8.x candidate). Decision at
  M44 pre-flight.
- **D5 — ERROR_CODES delta.** Likely zero (registry stays at 29).
  Existing `validation_failed` covers cap violations + deprecated-
  arg rejections.

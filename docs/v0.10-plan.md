### M53 — NOUN_DESCRIPTIONS single-source-of-truth lift (pre-flight CLOSED 2026-05-22, `c48510f`)

**Probe basis:** none required (§2). Pre-flight observation is the
call-site enumeration: 122 call sites collapsing to 18 canonical
noun keys (19 currently-active literal pairs in source — the 19th
is the R-v0.10-NEW-1 `update` drift that the IMPL migration drops).

**Headline finding (drove the scope).** Pre-flight enumeration
surfaced a SECOND active drift in `update/upload.ts:110` that pre-
dates M53 by months. The previous-known drift (`doc` "read-only at
v0.4") was the cited motivation when R-v0.8-NEW-22 was filed; the
second instance crystallises the rule-of-three (one bug from v0.5,
one from v0.8, one from v0.10's own pre-flight enumeration). The
lift addresses the bug *class*, not the individual instances —
once the map is the source of truth, divergence is structurally
impossible.

**Decision: ADDITIVE PRE-FLIGHT** (the 4-D choices below; no user
escalation needed — the constraints are unambiguous given the
existing call-site shape + the handoff's pre-flight scope).

- **D1 — Group-tier keying: FLAT noun-stem.** The map keys are
  plain noun strings (`'sprint'`, `'epic'`, `'time-track'`, …) —
  not `'dev.sprint'` / `'item.time-track'`. Trade-offs:
  - **Flat noun-stem (chosen).** No collisions today across the 18
    nouns. Simplest lookup (`NOUN_DESCRIPTIONS[name]`). Project
    rule "don't design for hypothetical future requirements" applies.
    A future collision (if a group-tier noun ever shared a name with
    a top-level noun, or two group-tier nouns under different
    parents collided) would NOT surface automatically: the lookup
    returns the same string for both registrations, and commander's
    find-or-create works against separate parent scopes, so both
    parents would render the same description silently. Mitigation
    is to **revisit the keying** when a collision actually appears
    — at that point the migration cost is small (the map already
    centralises the strings), so the optionality is preserved.
  - **Path-keyed (`noun.group`).** Future-proof against name
    collisions. Costs a context-aware lookup signature
    (`ensureSubcommand` would need to derive the parent-chain key
    from the `program` arg) — surface complexity for a problem
    nobody has today. Defer until a collision actually surfaces.
- **D2 — Signature shape: ADDITIVE** —
  `ensureSubcommand(program, name, summary?)` with `summary` made
  optional + falling back to `lookupNounDescription(name)`. All ~120
  existing call sites compile unchanged at pre-flight; M53 IMPL drops
  the 3rd arg from each call. Trade-offs:
  - **Additive (chosen).** Matches the pre-flight contract diff
    discipline ("pre-flight ships stubs additively; IMPL flips the
    runtime"). Single function — easy to test, easy to grep for
    migration progress (the IMPL hand-off section below pins the
    deterministic `rg` commands; the count starts at 122 and
    drops to 0 as IMPL migrates). Explicit summary override wins
    (matches commander.js precedent — most-specific source wins).
  - **Replace (3rd arg drops).** Forces all ~120 sites to migrate
    at pre-flight — bigger blast radius, no migration window, the
    pre-flight commit becomes the IMPL commit. Defeats the
    pre-flight discipline's separation of contract surface from
    runtime migration.
- **D3 — Map location: NEW `src/commands/noun-descriptions.ts`.**
  Trade-offs:
  - **New module (chosen).** SRP — the map is *concrete data*,
    `types.ts` is *pure interface + helper*. New module is small
    (~80 lines incl. the lookup helper + JSDoc), focused, easy to
    grep. ~80 future verb files will import the helper indirectly
    via `ensureSubcommand` (no direct import surge from this lift).
  - **Extend `types.ts`.** Adds ~80 lines of concrete data to
    what's currently 80 lines of types + a single helper. Mixes
    purposes; the file's name (`types`) no longer matches its
    content. Marginal save (one fewer file) doesn't justify the
    SRP loss.
- **D4 — Test contract** (`tests/unit/commands/types.test.ts`).
  The new test surface pins:
  1. **Lookup happy path** — `ensureSubcommand(program, 'config')`
     finds `NOUN_DESCRIPTIONS.config` and uses it as
     `description()`.
  2. **Find-or-create preserved** — second call with the same name
     returns the same Command instance (not re-created).
  3. **Multi-noun isolation** — `'config'` + `'cache'` create
     distinct commands matched by name only.
  4. **Explicit override wins** — passing a 3rd arg uses that
     string verbatim instead of the map (M53 IMPL-migration window
     contract).
  5. **Override-on-existing is ignored** — find-or-create wins; a
     2nd call with override on an existing noun returns the
     existing Command unchanged (matches the silent-drift bug
     class — second drift literals never overrode the first; the
     map removes the drift, the find-or-create semantics stay).
  6. **Strict-mode rejection** — `ensureSubcommand(program,
     'nonexistent-noun')` throws `InternalError` with
     `details.reason: 'unknown_noun'` + `noun` + `known_nouns[]`.
     This catches typos / missing-map-entries at registration time
     (commander's startup walk of the command registry fires the
     throw before the user sees `--help`).
  7. **Override bypasses lookup** — `ensureSubcommand(program,
     'unknown-noun', 'Explicit')` succeeds; the map IS the source
     of truth ONLY when the override is absent.
  8. **`NOUN_DESCRIPTIONS` shape invariants** — 18 entries (the
     pre-flight enumerated set); every entry is a non-empty
     string; no entry contains internal-doc references
     (`cli-design §`, `v0.x-M`, `deferred_to`, `TODO`, `FIXME`) —
     `feedback_public_docs_clean` enforced at the test boundary.
  9. **`lookupNounDescription` direct contract** — returns the
     mapped string; throws `InternalError` with structured
     `details` on miss.

  Tests drive the real production `NOUN_DESCRIPTIONS` map + real
  `Command` (not hand-shaped per `testing.md`). 12 tests total;
  all pass on the pre-flight commit.

- **D5 — ERROR_CODES delta.** ZERO. Registry stays 29. The
  `lookupNounDescription` rejection throws `InternalError` with a
  NEW `details.reason: 'unknown_noun'` discriminator — adds to the
  existing `internal_error` code's discriminator family, no new
  top-level code. 118 commands unchanged (no new verb).
